اندازه‌گیری یک آزمایش با یک نتیجه ساختارمند است. آنچه رخ داده را ثبت می‌کند، نه معنی آن را: اندازه‌گیری ناموفق یک شاهد است و تفسیر شواهد کار دستورهای بعدی است. همه‌چیز روی دستگاه خودتان اجرا می‌شود و nw جز بسته‌های خود آزمایش‌ها چیزی به جایی نمی‌فرستد.

هر اندازه‌گیری شناسه، نوع، وضعیت، زمان شروع و پایان، مدت، مقصد، و یک نتیجه یا یک خطا دارد. همه فیلدها در [طرح گزارش](../report-schema/) آمده‌اند.

## وضعیت‌ها

| وضعیت | معنی |
|---|---|
| `success` | اندازه‌گیری کامل شد و بررسی موفق بود |
| `failure` | اندازه‌گیری اجرا شد و بررسی موفق نبود؛ `error.code` می‌گوید چگونه |
| `skipped` | مرحله‌ای که به آن وابسته است شکست خورد و اجرا نشد؛ `note` دلیل را می‌گوید |
| `inconclusive` | اجرا شد ولی چیزی را ثابت نمی‌کند (برای دستورهای بعدی نگه داشته شده) |

## DNS

دستور `nw test dns <host>` رکوردهای A و AAAA یک نام را همزمان می‌پرسد.

- **resolver سیستم** همیشه اول و به‌عنوان مبنا اندازه‌گیری می‌شود. از resolver خود سیستم‌عامل استفاده می‌کند، پس مثل برنامه‌های شما رفتار می‌کند: فایل hosts و دامنه‌های جستجو را رعایت می‌کند. سرورهای نامی که سیستم شما با آن‌ها تنظیم شده در `resolver.servers` فهرست می‌شوند. سیستم‌عامل کد پاسخ DNS را گزارش نمی‌کند، پس برای مبنای سیستم، NXDOMAIN و پاسخ خالی هر دو `dns.no_answer` گزارش می‌شوند.
- هر **`--resolver`** مستقیم پرسیده می‌شود، با UDP (و در صورت کوتاه‌شدن پاسخ، دوباره با TCP) یا برای `tcp://` با TCP. این‌ها کد دقیق پاسخ (`NOERROR`، `NXDOMAIN`، `SERVFAIL`، `REFUSED`)، زنجیره CNAME و زمان‌ها را گزارش می‌کنند.
- نامی که رکورد A دارد ولی AAAA ندارد **موفق** است. نبود AAAA عادی است و هرگز خرابی IPv6 حساب نمی‌شود. نتیجه هر نوع، شاهد را نگه می‌دارد.
- تفاوت بین resolverها یک مشاهده است. DNS تفکیکی، CDNها، حافظه نهان و جغرافیا همگی تفاوت‌های مشروع ایجاد می‌کنند.

| کد خطا | معنی |
|---|---|
| `dns.nxdomain` | resolver گفت این نام وجود ندارد |
| `dns.no_answer` | نام هست ولی رکورد A یا AAAA ندارد (برای مبنای سیستم، «پیدا نشد» هم همین است) |
| `dns.servfail` | resolver هنگام پاسخ دادن خطا گزارش کرد |
| `dns.refused` | resolver از پاسخ دادن خودداری کرد |
| `dns.timeout` | تا پایان مهلت پاسخی نیامد |
| `dns.transport` | اصلاً نتوانست به resolver برسد |
| `dns.error` | کد پاسخ دیگر |

## TCP

دستور `nw test tcp <host:port>` میزبان را resolve می‌کند (نام به DNS نیاز دارد، آدرس IP ندارد) و روی پورت به هر آدرس، IPv4 و IPv6 جداگانه، وصل می‌شود. اتصال بلافاصله پس از برقرار شدن بسته می‌شود و چیزی فرستاده نمی‌شود.

| کد خطا | معنی |
|---|---|
| `tcp.refused` | مقصد پاسخ داد که چیزی روی این پورت گوش نمی‌دهد |
| `tcp.timeout` | تا پایان مهلت پاسخی نیامد (بسته‌ها حذف یا فیلتر شده‌اند) |
| `tcp.unreachable` | مسیری به شبکه یا میزبان وجود ندارد |
| `tcp.reset` | اتصال ریست شد |
| `tcp.error` | خطای دیگر سیستم‌عامل |

## TLS

دستور `nw test tls <host[:port]>` با هر آدرس دست‌دهی را کامل می‌کند و زنجیره گواهی و نام را تأیید می‌کند. تأیید همیشه روشن است و گزینه‌ای برای خاموش کردنش وجود ندارد. گزارش جزئیات گواهی را حتی وقتی تأیید شکست بخورد نگه می‌دارد، چون شاهد هستند: موضوع (subject)، صادرکننده، بازه اعتبار، نام‌ها (SAN) و اینکه زنجیره تأیید شد یا نه.

خطاهای گواهی از خطاهای دست‌دهی جدا نگه داشته می‌شوند، چون علت‌ها و قدم‌های بعدی فرق دارند.

| کد خطا | معنی |
|---|---|
| `tls.cert_expired` | گواهی منقضی شده یا هنوز معتبر نشده است |
| `tls.cert_untrusted` | زنجیره به یک مرجع مورد اعتماد نمی‌رسد |
| `tls.hostname_mismatch` | گواهی برای نامی که خواستید معتبر نیست |
| `tls.handshake_failure` | دست‌دهی به دلیل دیگری شکست خورد، مثلاً هشدار از سرور، سروری که TLS نمی‌فهمد، یا اتصال بسته‌شده |
| `tls.reset` | اتصال هنگام دست‌دهی ریست شد |
| `tls.timeout` | دست‌دهی تا پایان مهلت تمام نشد |
| `tls.error` | شکست دیگر |

شکست دست‌دهی می‌تواند علت‌های زیادی داشته باشد: تنظیم سرور، تنظیم کلاینت، یک پروکسی، یا دخالت در مسیر. گزارش آنچه دیده شده را می‌گوید و حدس نمی‌زند کدام است.

## HTTP

دستور `nw test http <url>` یک درخواست می‌فرستد، `GET` مگر اینکه `--method HEAD` بدهید، و تا `--max-redirects` تغییر مسیر را دنبال می‌کند. درخواست مستقیم می‌رود: متغیرهای محیطی پروکسی نادیده گرفته می‌شوند تا خود مسیر را اندازه بگیرید.

- هر درخواست در زنجیره یک **hop** با زمان‌بندی خودش است: DNS، اتصال، TLS، اولین بایت و کل، به میلی‌ثانیه. مرحله‌ای که رخ نداده، مثل TLS در HTTP ساده، حذف می‌شود.
- تا 1 مگابایت از بدنه خوانده و دور ریخته می‌شود، پس زمان کل انتقال را هم دربر می‌گیرد. **بدنه، کوکی و سرآیند Authorization هرگز ذخیره نمی‌شوند.** فقط فهرست کوتاهی از سرآیندهای پاسخ که به عیب‌یابی کمک می‌کنند نگه داشته می‌شود.
- پاسخ با هر کد وضعیتی یک اندازه‌گیری کامل‌شده است. `503` یک `success` با `status_code: 503` است؛ اینکه مشکل است یا نه را دستورهای بعدی قضاوت می‌کنند.
- خطاهای مرحله‌های پایین‌تر با کد خودشان گزارش می‌شوند، پس درخواست HTTP که در TLS شکست بخورد `tls.cert_expired` می‌گوید، نه یک خطای کلی HTTP.

| کد خطا | معنی |
|---|---|
| `http.timeout` | پس از برقراری اتصال، تا پایان مهلت پاسخ کاملی نیامد |
| `http.redirect_loop` | یک URL دو بار درخواست شد، یا تغییر مسیرها از حد مجاز بیشتر بود |
| `http.protocol_error` | پاسخ سرور HTTP معتبر نبود، یا تغییر مسیر به جای پشتیبانی‌نشده رفت |
| `http.reset` | اتصال پس از برقراری ریست شد |
| `http.error` | شکست دیگر |

به‌علاوه همه کدهای `dns.*`، `tcp.*` و `tls.*` بالا، وقتی شکست در همان مرحله رخ داده باشد.

## مهلت‌ها

`--timeout` (پیش‌فرض 10 ثانیه) مهلت هر اندازه‌گیری است. با Ctrl-C اجرا را متوقف کنید: nw اتصال‌هایش را می‌بندد، چیز ناقصی چاپ نمی‌کند و با وضعیت 130 خارج می‌شود.
