گاهی مقصدی شکست می‌خورد یا متفاوت پاسخ می‌دهد، چون چیزی میان شما و آن مقصد ترافیک را متفاوت رفتار می‌کند: فیلتر DNS، پروکسی، یا دستگاهی که اتصال را ریست می‌کند یا به آن پاسخ می‌دهد. `nw security interference` **نشانه‌های** چنین چیزی را جست‌وجو می‌کند. مقایسه می‌کند که طرف‌های مختلف چه برمی‌گردانند و یک درخواست وقتی یک چیز تغییر کند چگونه رفتار می‌کند. نتیجه نمی‌گیرد که دخالتی رخ داده است. یک timeout یا یک ناهمخوانی تنها توضیح‌های عادی فراوان دارد و هر یافته می‌گوید چه چیز دیگری می‌تواند آن را ایجاد کند و چه چیزی بررسی نشده.

```sh
nw security interference example.com --resolver tls://9.9.9.9 --resolver 1.1.1.1
nw diagnose example.com --profile deep      # همین پروب‌ها را شامل می‌شود
```

## چه چیزی را مقایسه می‌کند

| بررسی | روش | یافته |
|---|---|---|
| پاسخ resolverها | resolver سیستم در برابر هر `--resolver`؛ وقتی هیچ آدرس مشترکی برنگردانند، nw به هر دو مجموعه آدرس هم وصل می‌شود | `DNS_ANSWER_MISMATCH` |
| آدرس خصوصی | نام عمومی که به آدرس خصوصی، loopback، link-local یا فضای مشترک تبدیل می‌شود | `DNS_PRIVATE_ADDRESS_FOR_PUBLIC_NAME` |
| چند پاسخ | یک پرس‌وجوی UDP ساده فرستاده می‌شود و nw تا 500 میلی‌ثانیه به گوش می‌ماند. resolver معمولاً یک بار پاسخ می‌دهد | `DNS_MULTIPLE_DIFFERENT_RESPONSES` |
| نام سرور | در یک آدرس، دست‌دهی با نام مقصد در برابر یک نام کنترل بی‌طرف | `TLS_SNI_DEPENDENT_FAILURE`، `TLS_RESET_AFTER_CLIENTHELLO` |
| تغییر مسیرها | تغییر مسیری که از دامنه ثبت‌شده مقصد خارج می‌شود | `HTTP_REDIRECT_TO_UNRELATED_HOST` |
| http و https | همان درخواست روی هر دو، با مقایسه محل پایان و دسته کد وضعیت | `HTTP_HTTPS_RESPONSE_DIFFERENCE` |
| چیزی برای مقایسه نبود | اجرا resolver مستقل، دست‌دهی کنترل یا مقایسه http نداشت | `INTERFERENCE_INSUFFICIENT_EVIDENCE` |

نام کنترل برای مقایسه نام سرور `www.example.org` است، مگر با `--control` نام دیگری بدهید. این دامنه برای مستندات رزرو شده است: بی‌طرف است و هیچ سرویس واقعی به آن پاسخ نمی‌دهد.

هر کدام از این‌ها در [یافته‌ها](../findings/) با شرایط اشتباه بودنشان آمده است.

## resolverهای رمزگذاری‌شده

resolver را با `--resolver` انتخاب می‌کنید و چهار شکل پذیرفته می‌شود:

| شکل | انتقال |
|---|---|
| `host`، `host:port`، `[v6]:port` | DNS ساده روی UDP (در صورت کوتاه شدن، TCP) |
| `tcp://host[:port]` | DNS ساده روی TCP |
| `tls://host[:port]` | DNS روی TLS، پیش‌فرض پورت 853 |
| `https://host[:port][/path]` | DNS روی HTTPS، پیش‌فرض پورت 443 و مسیر `/dns-query` |

DNS ساده را هر چیزی در مسیر می‌تواند بخواند و به آن پاسخ دهد. پرسیدن از همان resolver روی TLS یا HTTPS این امکان را برمی‌دارد، پس تفاوت پاسخ ساده و رمزگذاری‌شده اطلاعات می‌دهد. گواهی سرور همیشه در برابر میزبان آدرس resolver تأیید می‌شود. برای نام میزبان (به‌جای آدرس IP) سیستم‌عامل آن را برای اتصال تبدیل می‌کند؛ همان یک جستجو از resolver سیستم استفاده می‌کند و اندازه‌گیری نمی‌شود.

## خواندن نتیجه

- **مشاهده اتهام نیست.** یافته‌ها می‌گویند چه دیده شد (مثلاً «یک پرس‌وجو دو پاسخ متفاوت گرفت»). فرضیه‌ها توضیح‌هایی پیشنهاد می‌کنند، از جمله توضیح‌های بی‌ضرر، با آنچه از هر کدام پشتیبانی می‌کند، آنچه علیه آن است و آنچه مشاهده نشده.
- **اطمینان سقف دارد.** هیچ فرضیه‌ای از یک اندازه‌گیری به `high` نمی‌رسد و بیشترشان `low` یا `medium` می‌مانند. یافته فقط وقتی `warning` است که چیزی جز خود تفاوت هم از آن پشتیبانی کند، مثلاً یکی از دو پاسخ وصل نشود.
- **سکوت یعنی «همه‌چیز سالم» نیست.** `INTERFERENCE_INSUFFICIENT_EVIDENCE` می‌گوید کدام مقایسه‌ها ممکن نبود. نبود یافته یعنی مقایسه‌هایی که انجام شد چیزی نشان نداد، نه اینکه هیچ مشکلی نیست.
- **از جای دیگر مقایسه کنید.** مفیدترین قدم بعدی تقریباً همیشه تکرار اجرا از شبکه یا دستگاهی دیگر است، تا ببینید تفاوت دنبال شبکه می‌آید یا نه.

## کار امن

nw فقط مقصدی را که نام می‌برید آزمایش می‌کند، با مجموعه کوچک و ثابتی از درخواست‌های اضافه: چند دست‌دهی بیشتر، یک پرس‌وجوی DNS بیشتر و یک درخواست http. هرگز پورت اسکن نمی‌کند، سوءاستفاده امتحان نمی‌کند و اعتبارنامه نمی‌آزماید؛ هر درخواست مهلت و سقف اندازه دارد؛ و هیچ تنظیمی را در سیستم شما تغییر نمی‌دهد. هرگز بر پایه یک مشاهده رویدادی را با اتهام برچسب نمی‌زند و هیچ قابلیت دور زدن محدودیت ندارد.

## بررسی‌های امنیتی دیگر

`nw security inspect` مشاهده‌های امنیتی‌ای انجام می‌دهد که به دخالت وابسته نیستند: آیا نام DNSSEC امضا دارد و resolver شما آن را تأیید می‌کند، زنجیره CNAME، چقدر به انقضای گواهی مانده، آیا سرور هنوز TLS 1.0 یا 1.1 را می‌پذیرد، آیا http به https ارتقا می‌یابد و آیا سایت `Strict-Transport-Security` می‌فرستد. [یافته‌ها](../findings/) را ببینید.

## پروب‌های مسیر

`nw path ping`، `nw path trace` و `nw path mtu` مسیر به یک مقصد را بررسی می‌کنند. ICMP اغلب فیلتر، کم‌اولویت یا محدود نرخ می‌شود، پس نبود پاسخ هرگز به‌عنوان مدرک خرابی یک مسیریاب یا مسدود بودن ترافیک نمایش داده نمی‌شود. جایی که ICMP به دسترسی‌ای نیاز دارد که ندارید، ping و trace از TCP استفاده می‌کنند و این را می‌گویند. هر پلتفرم چه چیزی را اجازه می‌دهد در [پشتیبانی از پلتفرم‌ها](../platform-support/) آمده است.
