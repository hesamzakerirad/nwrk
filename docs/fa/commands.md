این صفحه آنچه nw امروز می‌تواند انجام دهد را توضیح می‌دهد. با انتشار هر دستور جدید، اینجا اضافه می‌شود.

با `--output json`، دستورهای `nw test` و `nw diagnose` یک [گزارش](../report-schema/) با طرح (schema) نسخه‌دار چاپ می‌کنند.

## nw version

نسخه، کامیت، تاریخ ساخت و پلتفرم را چاپ می‌کند. هیچ درخواست شبکه‌ای نمی‌فرستد.

```sh
nw version
nw version --output json
```

دستور `nw --version` فقط شماره نسخه را چاپ می‌کند.

## nw test

یک اندازه‌گیری را اجرا می‌کند و آنچه دیده را چاپ می‌کند. هر اندازه‌گیری مستقل است: می‌توانید `nw test tls` را بدون اجرای چیز دیگری اجرا کنید. اینکه هر اندازه‌گیری چه می‌کند و خطاهایش چه معنی‌ای دارند، در صفحه [اندازه‌گیری‌ها](../measurements/) آمده است.

| دستور | چه چیزی را اندازه می‌گیرد |
|---|---|
| `nw test dns <host>` | جستجوی A و AAAA، با resolver سیستم و هر `--resolver` که اضافه کنید |
| `nw test tcp <host:port>` | یک اتصال TCP به همه آدرس‌های میزبان |
| `nw test tls <host[:port]>` | یک دست‌دهی TLS با تأیید گواهی، با همه آدرس‌ها (پیش‌فرض پورت 443) |
| `nw test http <url>` | یک درخواست HTTP یا HTTPS با زمان‌بندی مرحله‌ها و زنجیره تغییر مسیر محدود |

```sh
nw test dns example.com
nw test dns example.com --resolver 1.1.1.1 --resolver tcp://9.9.9.9
nw test tcp example.com:443
nw test tls example.com
nw test http https://example.com --output json
```

گزینه‌های `nw test`:

| گزینه | مربوط به | معنی |
|---|---|---|
| `--resolver` | هر چهار | یک resolver که کنار resolver سیستم اندازه‌گیری می‌شود. قابل تکرار. `host`، `host:port`، `[v6]:port` یا `tcp://host[:port]`. میزبان باید آدرس IP باشد. |
| `--method` | `http` | `GET` (پیش‌فرض) یا `HEAD`. روش‌های دیگر پشتیبانی نمی‌شوند. |
| `--max-redirects` | `http` | تعداد تغییر مسیرهای قابل دنبال کردن، از 1 تا 50. پیش‌فرض 10. |

فهرست resolverها از اولین منبعی که آن را تعیین کند گرفته می‌شود: گزینه‌های `--resolver`، سپس متغیر محیطی `NW_RESOLVERS` (جداشده با ویرگول). resolver سیستم همیشه اندازه‌گیری می‌شود، تا نتیجه resolverهای انتخابی شما با آن مقایسه شود و هرگز بی‌صدا جایگزینش نشوند. وقتی resolver را مشخص می‌کنید، `tcp`، `tls` و `http` به آدرس‌هایی وصل می‌شوند که همان resolver برگردانده است.

وضعیت خروج: `0` وقتی همه اندازه‌گیری‌ها موفق بودند، `1` وقتی دست‌کم یکی شکست خورد، `2` برای خطای استفاده. اندازه‌گیری‌ای که چون مرحله قبل شکست خورده اجرا نشده، `skipped` گزارش می‌شود و به‌تنهایی شکست حساب نمی‌شود. پاسخ HTTP با وضعیت خطا مثل 404 یا 503 یک اندازه‌گیری کامل‌شده است و با کد `0` خارج می‌شود؛ کد وضعیت در گزارش آمده است.

`--timeout` مهلت هر اندازه‌گیری را تعیین می‌کند. `--quiet` فقط اندازه‌گیری‌های ناموفق را چاپ می‌کند.

## nw diagnose

یک مقصد را در لایه‌های DNS، TCP، TLS و HTTP بررسی می‌کند و توضیح می‌دهد شواهد چه چیزی را نشان می‌دهند. نحوه کار و خواندن گزارش در [عیب‌یابی یک مقصد](../diagnostics/) و همه قاعده‌ها در [یافته‌ها](../findings/) آمده است.

```sh
nw diagnose example.com
nw diagnose https://example.com/health --profile deep
nw diagnose example.com:8443 --resolver 1.1.1.1 --output json
```

| گزینه | معنی |
|---|---|
| `--profile` | `quick`، `standard` (پیش‌فرض) یا `deep` |
| `--resolver` | یک resolver برای مقایسه با resolver سیستم؛ همان نحو و `NW_RESOLVERS` دستور `nw test` |

مقصد یک نام میزبان، `host:port` یا یک URL است. میزبان تنها یعنی https روی پورت 443 و پورت 80 یعنی http.

وضعیت خروج: `0` وقتی یافته قابل اقدامی نبود، `1` وقتی مقصد مشکل دارد، `2` برای خطای استفاده، `130` هنگام توقف. `--quiet` فقط یافته‌ها را چاپ می‌کند؛ `--verbose` جزئیات هر اندازه‌گیری را اضافه می‌کند.

## nw doctor

وضعیت شبکه خود این دستگاه را بررسی می‌کند، سپس هدف‌های مرجع یک پیش‌تنظیم منطقه را، و می‌گوید مشکل **محلی**، **داخلی** یا **بین‌المللی** است. آنچه انجام می‌دهد، حکم‌ها و همه هدف‌های مرجع در [منطقه‌ها و پیش‌تنظیم‌ها](../regions/) و آنچه با آن تماس می‌گیرد در [حریم خصوصی](../privacy/) آمده است.

```sh
nw doctor
nw doctor --region ir
nw doctor --region ir --resolver 1.1.1.1 --resolver tcp://9.9.9.9 --output json
```

قالب گزارش مثل `nw diagnose` است، با `summary.verdict` و وضعیت هر محدوده. `--region` برابر global، `ir` یا هر پیش‌تنظیم دیگر است؛ پیش‌فرض `global`. وضعیت خروج مثل `nw diagnose`: `0` یافته قابل اقدامی نیست، `1` مشکل، `2` خطای استفاده، `130` متوقف‌شده.

## nw network

وضعیت شبکه خود این دستگاه را از سیستم‌عامل می‌خواند. هیچ‌چیز روی شبکه فرستاده نمی‌شود. این دستورها آدرس‌ها را نشان می‌دهند، چون هدفشان همین است.

| دستور | نشان می‌دهد |
|---|---|
| `nw network show` | خلاصه کوتاه: رابط‌ها، مسیر پیش‌فرض، سرورهای DNS، پروکسی |
| `nw network interfaces` | رابط‌ها با وضعیت، MTU و آدرس‌ها |
| `nw network routes` | جدول مسیریابی (در ویندوز در دسترس نیست) |
| `nw network dns-config` | سرورها و دامنه‌های جستجوی DNS که سیستم به کار می‌برد |
| `nw network proxy` | تنظیمات پروکسی که برنامه‌ها ممکن است به کار ببرند، بدون اعتبارنامه |

اینکه هر پلتفرم چه چیزی را می‌تواند نشان دهد در [پشتیبانی از پلتفرم‌ها](../platform-support/) آمده است.

## nw config

nw یک فایل TOML اختیاری می‌خواند. `nw config path` محل آن را چاپ می‌کند (چه وجود داشته باشد چه نه) و `nw config show` تنظیمات مؤثر را با منبع هر کدام نشان می‌دهد.

```sh
nw config path
nw config show
```

```toml
region = "ir"
resolvers = ["1.1.1.1", "tcp://9.9.9.9"]
timeout = "5s"
color = "auto"   # auto، always یا never
```

| پلتفرم | محل |
|---|---|
| لینوکس | `$XDG_CONFIG_HOME/nwrk/config.toml`، وگرنه `~/.config/nwrk/config.toml` |
| macOS | `~/Library/Application Support/nwrk/config.toml` |
| ویندوز | `%LOCALAPPDATA%\nwrk\config.toml` |

متغیر `NW_CONFIG` محل را تغییر می‌دهد. کلید ناشناخته خطا است، تا غلط املایی بی‌صدا بی‌اثر نماند. nw هرگز فایل را نمی‌نویسد و اعتبارنامه نباید در آن باشد.

**هر تنظیم از یک ترتیب پیروی می‌کند:** گزینه خط فرمان، سپس متغیر محیطی `NW_*`، سپس فایل پیکربندی، سپس پیش‌فرض.

| تنظیم | گزینه | متغیر | پیش‌فرض |
|---|---|---|---|
| `region` | `--region` | `NW_REGION` | `global` |
| `resolvers` | `--resolver` | `NW_RESOLVERS` | هیچ (سپس مال پیش‌تنظیم، [منطقه‌ها](../regions/) را ببینید) |
| `timeout` | `--timeout` | `NW_TIMEOUT` | `10s` |
| `color` | `--no-color` | `NW_COLOR` | `auto` |

`NO_COLOR` و `--no-color` همیشه بر `color = "always"` غلبه می‌کنند.

## nw completion

اسکریپت تکمیل خودکار را برای `bash`، `zsh`، `fish` یا `powershell` تولید می‌کند. هیچ درخواست شبکه‌ای نمی‌فرستد.

```sh
# bash: برای نشست فعلی
source <(nw completion bash)

# zsh: قرار دادن در مسیر توابع
nw completion zsh > "${fpath[1]}/_nw"

# fish
nw completion fish > ~/.config/fish/completions/nw.fish

# PowerShell
nw completion powershell | Out-String | Invoke-Expression
```

## گزینه‌های سراسری

| گزینه | معنی | پیش‌فرض |
|---|---|---|
| `-o`، `--output` | `human` یا `json` | `human` |
| `--no-color` | خاموش کردن رنگ خروجی | رنگ برای ترمینال روشن است |
| `-v`، `--verbose` | نمایش جزئیات بیشتر و لاگ‌های اشکال‌زدایی در stderr | خاموش |
| `-q`، `--quiet` | پنهان کردن خروجی غیرضروری؛ خطاها و کد خروج می‌مانند | خاموش |
| `--timeout` | مهلت هر عملیات شبکه، مثلاً `5s` | `10s` |
| `--region` | پیش‌تنظیم منطقه: `global` یا `ir` | `global` |

گزینه‌های `--verbose` و `--quiet` را نمی‌توان با هم به کار برد.

## کدهای خروج

| کد | معنی |
|---:|---|
| `0` | دستور اجرا شد و مشکلی پیدا نکرد |
| `1` | دستور اجرا شد و مشکلی در مقصد پیدا کرد |
| `2` | خطای استفاده (گزینه، مقصد یا تنظیم نادرست)، یا nw نتوانست اندازه‌گیری را اجرا کند |
| `130` | شما دستور را با Ctrl-C متوقف کردید |

برای `nw diagnose`، کد `1` یعنی دست‌کم یک یافته `error` یا `warning`. برای `nw test`، کد `1` یعنی یک اندازه‌گیری شکست خورده است. مشکل داشتن مقصد شبکه یک نتیجه است (کد `1`) و خطای ابزار نیست (کد `2`).

## قراردادهای خروجی

- نتیجه‌ها در stdout نوشته می‌شوند. لاگ‌ها، پیشرفت و خطاها در stderr می‌روند؛ پس می‌توانید نتیجه را با خیال راحت به فایل یا دستور دیگر بدهید.
- رنگ فقط وقتی استفاده می‌شود که stdout یک ترمینال باشد. برای pipe و فایل، با `--no-color`، با متغیر محیطی `NO_COLOR` و وقتی `TERM=dumb` است خاموش می‌ماند. رنگ هرگز تنها راه بیان یک نتیجه نیست.
- با `--output json` هر سند فیلد `schema_version` دارد. خطاها هم به صورت JSON در stderr نوشته می‌شوند:

```json
{"schema_version":"1","error":{"kind":"usage","message":"invalid --output \"xml\" (want human or json)"}}
```

مقدار `kind` وقتی `usage` است که nw اشتباه صدا زده شده باشد و وقتی `execution` است که خود nw نتوانسته کارش را انجام دهد. هر دو با کد 2 خارج می‌شوند.
